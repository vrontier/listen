Welcome, {{.Name}}

The Workbench analyses live audio streams for you: it finds spectral events and recurring motifs in each source, compares sources with each other, and records what a run finds as a data set to download. This is the way through it, step by step, with where you stand at each step.

  1. Register a source

    A source is a live audio stream you are allowed to analyse: your own receiver's, or one whose operator agreed. Give its address under Register a source; the Workbench listens to it briefly to learn its format and sample rate. The Workbench connects to a source only while an analysis that uses it is in a run or a preview. A new source starts as a draft; put it in service once it proves reliable (both connect alike for now). You can share a source with other members on its page, and use sources others share with you.

    Now: {{.Sources}} source{{if ne .Sources 1}}s{{end}} of your own{{if .Shared}}, {{.Shared}} shared with you{{end}}. Sources

  2. Make an analysis

    An analysis listens to one or more sources, up to {{.MaxSources}}, with settings of its own for each: the frequency range, how sensitive it is, filter rules that leave out known interference such as mains hum, and whether it keeps what it learns. Make one under New analysis. Start a ten-minute preview on its page to watch the live spectrogram and events and to tune the settings; a preview records nothing. Every saved change is a new revision.

    Now: {{.Analyses}} analys{{if eq .Analyses 1}}is{{else}}es{{end}}. Analyses

  3. Start a run

    A run keeps an analysis listening for a set time, or until you stop it, whether or not a page is open. Its settings are fixed while it lasts; to try changed settings, start a trial next to it on the analysis's page. A run stops by itself when a source sends nothing for a while (you choose how long), and you get a mail when it ends without your stopping it. Start one on the analysis's page or under Runs.

    Now: {{if .Running}}{{.Running}} running{{else}}nothing running{{end}}, {{.Finished}} finished. Runs

  4. Look at the results

    Each finished run leaves a data set: the events of every source and of the comparison, with the times a source was not heard, as JSON and CSV. Download it under Results, as one zip or file by file, and delete what you no longer need there: data sets and the analyses' memories share your disk space, and a run is refused while it is full.

    Now: {{.Datasets}} data set{{if ne .Datasets 1}}s{{end}}; {{bytes .Disk.Total}} of {{bytes .Quota}} used ({{.UsedPct}} %). Results

  5. Work with an AI assistant or a program

    A token lets an AI assistant (through MCP) or your own program (through the data stream) read your analyses, their live events and your data sets. Make one under AI, Access; a token reads only, unless you allow it more.

    With control allowed for a token, an assistant can also work for you: list your sources, make an analysis, rename it, choose its sources and tune their settings and filter rules (each change a new revision, checked by the engine), preview it for ten minutes, and start and stop runs. You set the limits per token, or none: the longest run, runs a day and at once, previews and changes a day. You get a mail whenever a token starts a run, and the run names the token. An assistant never registers, shares, publishes or deletes anything.

    For long sessions an assistant can ask for a short summary of an analysis and, during a run, only what is new since it last looked. The AI pages say how to give an assistant access step by step, list every tool it can call with a guide to give it and how to connect, and show everything done with your tokens, the changes marked.

  6. Publish

    When you choose, publish an analysis on its page: it then appears to everyone under Research, with its live view while it runs and, if you offer them, its data sets. You can withdraw it at any time.
